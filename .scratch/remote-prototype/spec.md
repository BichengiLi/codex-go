# 首个远程开发原型

## Problem Statement

使用 API Key 的用户缺少手机入口，无法便捷地连接自己电脑上的 Codex 项目和已有会话。当前仓库只有方案文档，关键协议尚未实测。

## Solution

交付可运行的 Node.js 主机服务和适配手机的网页客户端，使用已安装的官方 Codex App Server。复用主机当前模型配置，也支持通过主机环境变量配置 Responses 服务。浏览器不接收模型密钥。Android 本地执行提供可重复的探针，实机支持单独判定。

## User Stories

1. 作为个人用户，我能在电脑启动服务，查看连接地址和短时配对码。
2. 作为手机用户，我能配对主机，查看授权项目，并退出或撤销设备。
3. 我能列出、阅读和接续授权目录中的已有会话，保持原会话 ID。
4. 我能在授权父目录创建空项目并新建会话。
5. 我能发出开发指令，看到实时输出、工具执行、文件改动和任务状态。
6. 我能接受或拒绝执行审批，停止自己通过连接服务发起的任务。
7. 断线后我能重新载入历史与待处理审批，重复提交不会再次执行。
8. 我能看见模型服务、主机和工作目录，并知道哪些兼容性尚未验证。

## Implementation Decisions

- TypeScript 主机连接服务 + React/Vite 手机网页；同源 HTTP 和 SSE，不暴露 App Server。
- 官方 stdio 双向 JSON-RPC，支持超时、进程退出、请求回调和通知。协议按本机 CLI 版本生成。
- 项目授权按真实路径验证，阻止目录穿越、符号链接和 junction 逃逸。授权目录不是模型工具的操作系统沙箱；工具权限依赖 Codex 自身策略。
- 主机默认只监听 loopback。远程使用 HTTPS 反向代理或 SSH/私有网络；明文局域网必须显式启用开发选项。
- 配对码 5 分钟有效、限流；随机设备凭据使用 HttpOnly/SameSite cookie，服务端只存哈希，支持撤销。
- 写操作校验 Origin 和 Host。API 仅暴露项目/会话/任务/审批等明确接口，不提供任意 RPC 通道。
- 客户端不自动重发任务；持久化请求标识，超时或进程重启后的不确定提交需要人工核对。
- 接续已有空闲会话前由用户确认桌面已停止操作。独立进程不能可靠判断桌面运行任务，不能承诺并发接管。
- 用户已于本轮选择复用电脑当前 Codex 配置进行真实模型验证。

## Testing Decisions

以 HTTP 边界和真实 stdio 子进程为主要验证入口，覆盖配对与撤销、来源校验、授权路径、流式事件、审批往返、重复提交和重连。使用可控协议进程验证故障情况，并提供显式调用的真实 Codex 探针；真实模型验证仅在独立临时项目和新会话进行。生产构建和 TypeScript 检查必须通过。

## Out of Scope

Android 原生安装器、iOS、P2P/中继、多人协作、自动迁移项目、任意桌面活动任务接管、仓库克隆与完整差异审阅器。网页仅作为首轮远程入口，原生路线保留。
