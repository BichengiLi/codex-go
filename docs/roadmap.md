# 推进路线

首个远程原型已落地。完整条目按实际验收勾选；部分实现用括号注明，未以桌面浏览器替代真实手机验收。

## 阶段 0：验证关键可行性

- [x] 固定一个 Codex CLI 版本，保存版本信息并生成对应协议 Schema。
- [x] 通过 App Server 完成新建会话、发起任务、流式输出和审批交互。
- [x] 使用一个用户选定的中转服务验证鉴权、Responses、工具执行及多轮上下文。
- [x] 验证能否发现并读取本机桌面 App 创建的会话。
- [ ] 验证空闲桌面会话在手机连接端接续后，桌面仍能继续同一会话。
- [x] 区分验证运行中会话的观察、控制和执行权交接能力（仅控制本服务创建的任务；桌面其他进程不承诺）。
- [ ] 参考 dsh-Go，在 Android 上验证 Codex 的启动、App Server 通信、文件读写和工具执行。
- [ ] 记录手机本地运行的权限、沙箱、资源与后台限制，决定原生客户端及首版范围。
- [ ] 给出结果记录与限制，决定公开接口是否足够、是否需要修改 CLI。

完成标准：使用真实项目记录一次电脑 → 连接端 → 电脑的会话往返，并给出手机本地运行的验证结论；对不支持的情况给出明确证据。阶段 0 可以先用最小协议客户端验证，不必先完成手机界面。

## 阶段 1：手机与个人电脑的首个闭环

- [x] 实现主机连接服务与手机可用的网页原型；正式客户端形态仍待 Android 验证。
- [ ] 完成设备配对、加密连接和凭据撤销（配对/撤销已实现，HTTPS 外部代理待部署验收）。
- [ ] 实现模型服务配置及连接诊断（当前复用主机配置或环境变量，诊断分类待完善）。
- [x] 实现授权项目列表和会话列表。
- [ ] 支持创建空项目、克隆仓库、新建对话和接续已验证的对话（除克隆外已实现，桌面往返验收待完成）。
- [ ] 显示流式输出、文件改动和任务状态；支持审批、停止和适用的补充指令（补充指令待实现）。
- [x] 实现断线恢复与重复提交保护（事件缺口补载历史；不确定提交不自动重发）。
- [ ] 在真实手机端与 Windows 主机上完成往返验收。

完成标准：手机可在电脑上的授权项目中完成一次实际开发任务，用户能理解执行状态，并能回到电脑继续工作。

## 阶段 2：无需个人电脑在线

- [ ] 手机本地运行可行时，完成运行环境安装、校验、启动、停止及故障恢复。
- [ ] 在手机本地完成 API 配置、项目创建、开发任务和会话恢复。
- [ ] 让同一连接服务支持用户自己的常驻 Linux 主机。
- [ ] 手机可切换主机，明确区分各主机的项目和会话。
- [ ] 在常驻主机上完成创建项目、配置模型服务和完整开发流程。
- [ ] 明确跨主机项目迁移、未提交改动传递及会话迁移的边界。

完成标准：关闭个人电脑后，手机能在本地环境或另一台已配置的运行主机上开展开发任务；两种模式分别记录支持状态。
