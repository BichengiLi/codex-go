# 推进路线

全部条目目前均未完成。下列顺序是初步建议。

## 阶段 0：验证关键可行性

- [ ] 固定一个 Codex CLI 版本，保存版本信息并生成对应协议 Schema。
- [ ] 通过 App Server 完成新建会话、发起任务、流式输出和审批交互。
- [ ] 使用一个用户选定的中转服务验证鉴权、Responses、工具执行及多轮上下文。
- [ ] 验证能否发现并读取本机桌面 App 创建的会话。
- [ ] 验证空闲桌面会话在手机连接端接续后，桌面仍能继续同一会话。
- [ ] 区分验证运行中会话的观察、控制和执行权交接能力。
- [ ] 参考 dsh-Go，在 Android 上验证 Codex 的启动、App Server 通信、文件读写和工具执行。
- [ ] 记录手机本地运行的权限、沙箱、资源与后台限制，决定原生客户端及首版范围。
- [ ] 给出结果记录与限制，决定公开接口是否足够、是否需要修改 CLI。

完成标准：使用真实项目记录一次电脑 → 连接端 → 电脑的会话往返，并给出手机本地运行的验证结论；对不支持的情况给出明确证据。阶段 0 可以先用最小协议客户端验证，不必先完成手机界面。

## 阶段 1：手机与个人电脑的首个闭环

- [ ] 实现主机连接服务与手机客户端；远程验证可先使用 PWA，正式形态结合阶段 0 决定。
- [ ] 完成设备配对、加密连接和凭据撤销。
- [ ] 实现模型服务配置及连接诊断。
- [ ] 实现授权项目列表和会话列表。
- [ ] 支持创建空项目、克隆仓库、新建对话和接续已验证的对话。
- [ ] 显示流式输出、文件改动和任务状态；支持审批、停止和适用的补充指令。
- [ ] 实现断线恢复与重复提交保护。
- [ ] 在真实手机浏览器与 Windows 主机上完成往返验收。

完成标准：手机可在电脑上的授权项目中完成一次实际开发任务，用户能理解执行状态，并能回到电脑继续工作。

## 阶段 2：无需个人电脑在线

- [ ] 手机本地运行可行时，完成运行环境安装、校验、启动、停止及故障恢复。
- [ ] 在手机本地完成 API 配置、项目创建、开发任务和会话恢复。
- [ ] 让同一连接服务支持用户自己的常驻 Linux 主机。
- [ ] 手机可切换主机，明确区分各主机的项目和会话。
- [ ] 在常驻主机上完成创建项目、配置模型服务和完整开发流程。
- [ ] 明确跨主机项目迁移、未提交改动传递及会话迁移的边界。

完成标准：关闭个人电脑后，手机能在本地环境或另一台已配置的运行主机上开展开发任务；两种模式分别记录支持状态。

## 阶段 3：日常使用体验

- [ ] 改进手机代码与差异阅读、历史搜索和长任务导航。
- [ ] 评估后台通知、跨网络连接和中继的实际需求。
- [ ] 增加兼容性记录、版本检查及升级恢复策略。
- [ ] 根据实际使用评估 iOS 客户端及其本地执行可行性。

## 开发前需要收敛的选择

优先验证真实中转协议、桌面会话接续路径和 Android 本地运行条件，再决定连接服务语言、界面框架、配对方案及公网连接方式。参考 [dsh-Go 实现分析](references/dsh-go.md)，不要用界面完成度代替核心能力的验证。
